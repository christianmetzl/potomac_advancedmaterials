# HamLib slice — third-party operators for offline cross-check

This directory bundles **only** the three Hydrogen-chain instances we validate against — H14/H16/H20
(STO-6G; 28/32/40 qubits) — extracted verbatim from the public **HamLib** archive
(Sawaya et al., *Quantum* 8, 1559, 2024; https://portal.nersc.gov/cfs/m888/dcamps/hamlib/). It exists so a
judge can run the **full third-party equivalence check with no external download**.

- `H{14,16,20}_sto6g_jw.qubitop.gz` — the genuine HamLib operator strings (gzipped), NOT regenerated by us.
- `provenance.json` — source URL, source-file SHA-256, matched keys, and the term-count/one-norm invariants.

**To populate** (run once, on any machine with internet — the build sandbox cannot reach NERSC):
```
python src/hamlib_extract_slice.py --file <downloaded-hamlib.hdf5>
git add data/hamlib_slice && git commit -m "Bundle HamLib H14/16/20 slice for offline cross-check"
```
The extractor self-validates each instance against the committed invariants in `src/hamlib_validate.py`
(term count + one-norm), so it can only ever emit correct, genuine HamLib data. Once bundled,
`python src/hamlib_validate.py 14` (or 16 / 20) prints a **FULL offline HamLib slice … MATCH** line —
a phase-invariant, coefficient-magnitude check of the complete operator, no download required.

Until then, the term-count + one-norm equivalence (committed in `hamlib_validate.py`) already holds
offline; this slice upgrades that scalar check to a full-operator one.
